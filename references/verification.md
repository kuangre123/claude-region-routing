# 出口与故障切换验证

1. 从运行配置找与目标地区对应的候选，如 SG/Singapore/新加坡 或 US/USA/美国及相应城市名。只读取所需的节点名、代理类型和路由状态。凭证、订阅链接、控制器密钥和真实出口地址不进终端输出、聊天或可分享配置。
2. 用客户端能指定单条线路的功能测试。仅测速的接口通常只能证明连接延迟；验证地区需要经过该节点的实际 HTTPS 响应。可用隔离的本地实例或测试代理监听分别直连候选，不切整机默认节点。隔离实例绑定 loopback，关闭 TUN 和系统代理接管；带凭证的临时配置限制为当前用户可读并在测试后清理。
3. 经明确的代理监听对 `https://claude.ai/cdn-cgi/trace` 和 `https://api.anthropic.com/cdn-cgi/trace` 发无凭证的 GET 请求。只取 `loc=US` 或 `loc=SG`，`colo` 表示 Cloudflare 机房。检查 curl 的实际退出码和 HTTPS 响应。没有 `loc` 时，用同一条测试线路访问可信 IP 地区服务，同时单独检查真实目标可达；如果按域名分流，普通 IP 查询站点不能代替 Claude 自身的路由证据。旧会话的地理标签也不能代替当前出口验证。
4. 为客户端内置的线路检测选能稳定通过其探测方法的 URL 和状态码。Mihomo 用 HEAD，Claude 网页可能对 HEAD 返回 403，即便 GET 正常。可先逐条测试 Anthropic API 根路径的 HEAD；两条线路均返回预期 404 时使用 `https://api.anthropic.com/` 配合 `expected-status: '404'`。若行为变化，重新选择并验证目标。自动健康检查测的是可达性，不能持续认证国家；订阅更新、节点更名或出口变化后重新检查。
5. 验证活动配置中的规则优先级、实际分组成员和新连接的策略链。确认 TCP、UDP/QUIC、IPv4/IPv6 在使用的客户端和节点能力下不会落入异地区默认路由。若某协议不能安全代理，优先对相同 Claude 目标使用客户端支持的专门拒绝规则并验证 TCP 回退，或明确报告无法保证的协议范围。
6. 在隔离实例或客户端的安全测试功能中令首选节点无法连接，等健康状态更新后重新发请求，核对策略链和地区。无法模拟时注明“已检查配置和正常出口，未实测掉线切换”。不关闭用户正在使用的会话来制造故障。对客户端看不到域名、第三方网关或绕过代理的请求，依据观察结果说明覆盖范围。
